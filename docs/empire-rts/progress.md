## 狀態規則

- TODO：尚未開始。
- IN_PROGRESS：已開始；記錄正在做什麼。
- PARTIAL：部分成果可驗證，但未滿足全部驗收。
- BLOCKED：記錄具體阻礙、已嘗試方法、解除條件與可繼續的獨立工作。
- DONE：全部必要驗收有實際證據，並有對應檔案／commit 和測試紀錄。

不用未經定義的整體完成百分比。任務數量或 Build 成功不代表遊戲完成。標為 DONE 時，證據至少包含版本、環境、操作或檢查方式、實際結果；涉及畫面的功能附截圖或錄影。

## 尚待定稿

- 正式名稱、兩時代的具體組合、完整時代表和文明背景。
- 後續跨平台支援、與 R28 相符的 C++ 原始碼基線（需要改引擎時）、硬體效能門檻；M1 首測平台與 runtime 已固定。
- 正式美術色票、比例、模型／貼圖規格與完整動畫表。
- 潛艇是否納入早期版本，以及是否需要任何引擎修改。

以上多數可在指定任務中提出可逆預設後驗證；不需要為每一個細節中斷工作。涉及預算或發布範圍變動則另外確認。

## 每次更新清單

1. 開始前讀取最新 master、相關規則、此表及最近 journal，保留其他人的變更。
2. 將實際開工項目標為 IN_PROGRESS，指定執行者與目前子任務。
3. 保存有意義的測試證據；不能用「應該可用」代替結果。
4. 更新狀態、未解問題與下一動作，在 journal 追加紀錄。
5. 提交實作時同步提交相關文件，記錄 commit；對外推送沿用有效授權範圍。
