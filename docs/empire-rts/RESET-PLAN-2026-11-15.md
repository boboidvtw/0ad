# 重設計畫

**狀態：APPROVED（2026-11-15，Q1–Q4 全部照建議）。** 本檔取代 `archive/PROJECT-ASSESSMENT-2026-11-05.md` 的 R01–R18 工作包，成為下一步的唯一依據；定案見 [decisions.md](decisions.md)，進度見 [STATUS.md](STATUS.md)。

## 1. 一句話

T14–T18 已有的成果全部保留，未通過的項目改記為「已知限制」並結案，停止追正式核可鏈；接下來兩個里程碑只做**玩家看得到差別**的東西，驗收方式回到 M1–M2 當時有效的做法。

## 2. 為什麼要重設

| 指標 | 數據（2026-11-15，`codex/t14-t18-closeout-20261115`） |
|---|---|
| 最後一個新增遊戲功能的 commit | `726a3ae` T13 存讀檔與網路（2026-09-29） |
| 之後的 commit | 5 個，全部是 `docs:` |
| 文件 vs Mod 程式碼 | `docs/empire-rts` 12,308 行 md／633 檔／53 MB；Mod 5,457 行 |
| 交接／收工檔 | 70 份 `SESSION-*.md`（根目錄 66、子目錄 4） |
| T17 工作包依賴鏈 | R01 → R02 → R03 → R05 → R08 → R09 → R11 → R13，第一步 R01 停在 `PENDING_USER_DECISION` |

根因（推測，信心中）：自主 session 每遇到一次失敗就加一層護欄（seal、guard age、三方核可、retry0、「不得改名重跑」），而護欄本身變成要被驗收的對象。這些規則都是專案自己定的，沒有外部要求，**可以撤銷**。

## 3. 新的工作規則（取代 T14–T18 期間累積的流程）

| 舊做法 | 新做法 | 理由 |
|---|---|---|
| 每案 retry0，失敗即永久保留 FAIL、不得重跑 | 失敗 → 修 → 重跑，直到通過；FAIL 紀錄留在 git 歷史即可 | 這是開發，不是法庭證據 |
| 三方（CODE／Python／JS-API）正式 DESIGN／SOURCE 核可 | 一次 code review（人或單一 reviewer agent）＋測試綠燈 | 單人專案，多方核可只增加等待 |
| SHA-256 seal、manifest、freshness guard（age≤60s） | 只在**發行包**做 checksum | 防竄改是發行需求，不是開發需求 |
| 每個 session 一份交接檔 | 只維護一份 `STATUS.md`（現況＋下一步，≤80 行）；細節寫在 commit message | 交接檔已經多到沒人會讀 |
| 「限定 DONE」「有界 DONE」「PARTIAL_REQUIRES_DISTINCT_SCOPE」 | 只用 `TODO／DOING／DONE／DROPPED`，DONE 的範圍寫一句話 | 狀態要讓人一眼看懂 |
| 文件中英混排加縮寫（`3casesNOT_RUN`、`新root本人3/85`） | 完整句子；縮寫第一次出現要解釋 | 三個月後的自己也要看得懂 |

### 完成定義（Definition of Done，每項任務一樣）

1. `tools/epoch-rts/smoke-macos.py` 對 seed 42、7 都通過（引擎 0 錯誤）。
2. 新功能有對應的自動化檢查（沿用 T04／T05 的 validation map script 寫法）。
3. 錄一段 1–3 分鐘遊玩影片或 3 張截圖，證明玩家看得到效果。
4. 舊回歸（M1 移動、T04 經濟、T05 研究）重跑仍通過。
5. 更新 `STATUS.md` 一行。

不做：封存 raw、逐檔 SHA、多 actor 讀回。

### Agent 自主執行的限制

- 一個任務連續 3 個 session 沒有新增 `feat:` 或 `fix:` commit → 自動停下，回報給本人，不再寫交接檔。
- Agent 不得自己新增驗收門檻或流程規則；要加，寫成提案等本人同意。
- 排程任務只能跑「測試＋回報」，不能自己開新工作包。
