## Selection, storage and memory

Use two phases within the same capture session: (A) enumerate and capture each candidate to owned output, retaining only layer metadata and held loose-source descriptors; (B) resolve highest-priority rows, enforce final candidate count/metadata/final selected byte limits, then load final selected bodies from the owned snapshots for the existing SOURCE/FINISH checks. No archive pathname reopen and no reread of original source to manufacture a second capture. Archive reads all continue through the same authenticated held FD. AFTER receiving and successfully validating the complete FINISH frame, and BEFORE writing successful analysis outputs/manifest/completed.json, recheck every original held loose-source FD (full bytes/digest and metadata), its parent/name identity, all retained source-directory identities, and output anchors. This terminal recheck is mandatory even if an earlier pre-FINISH check was performed; an earlier check never substitutes for it. Source change while Node analyses or waits must fail this same case. This preserves the ordering in base PROTOCOL step5 and current preimage validate_finish -> capture.recheck -> source cleanup -> output.check -> successful outputs. No healthy completion after a failed or UNKNOWN recheck/cleanup.

Single-file uncompressed 8 MiB applies separately to every candidate in every layer. Enforce advertised size before allocation when available and actual bounded read size/CRC afterward. selectedTotalMaxBytes=67,108,864 counts each final VFS exactly once, after overrides; never apply it to archive-only or all-layer sums. Metadata total remains 8 MiB over all five mod.json bodies. candidateCountMax=4096 is the unique final VFS union; candidateLayerEntryCountMax=16384, path/ZIP limits and all other base limits remain unchanged. Reject too many unique candidate VFS before body capture where enumeration permits; do not treat early partial evidence as a complete capture.

Do not add an independent all-layer 64 MiB/320 MiB cap. Such a cap could reject valid final-selected inputs merely because lower-layer bodies are larger. The existing structural bounds imply at most 5*4096*8 MiB=171,798,691,840 bytes of layer-source payload on a successful capture (five layers, unique VFS per layer, final union at most4096). This is a derived worst-case bound, not a target or reserved space and not permission for a stress run. Disk errors, 600-second wall deadline and existing resource failures remain terminal and retain partial evidence. Official capture still requires later full source reviews and root authorization; no automatic large archive run or new workload is authorized by this design.

During phase A hold at most one transient source body (8 MiB), the authenticated reader's one4MiB cache, bounded ZIP buffers/metadata, plus already-existing protocol buffers. Do not keep archivebody, per-layer body dictionaries or a full layer-source pack in RAM. During phase B retained final selected bodies sum to at most64MiB; source-readback/validation/base64/NDJSON serialization incur explicit bounded additional copies (existing frame/raw/analysis limits still apply). Revalidation of loose sources reads one file at a time. This is an allocation design obligation; one-cache configuration alone is not measured RSS proof. Tests must instrument live body retention and request sizes, separately reporting any measured memory context without inventing an absolute RSS guarantee.
